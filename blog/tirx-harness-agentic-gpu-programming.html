TIRx Harness：让 Agent 少猜编译器，多做有效优化

一句话判断

Architecture

四层环境：压缩 Agent 的不确定性

Agent 的主要消耗不是“生成一段 CUDA”，而是反复预测编译行为、诊断偶发错误、重建已知优化知识，以及在被污染的 GPU 计时里选择错误方向。

TIRx-lite

贴近 PTX 的最小编程面，显式表达寄存器、共享内存、同步、warp role 与执行坐标，减少高层 lowering 的语义猜测。

正确性工具

Synccheck、Racecheck、NumSim 与 Compute Sanitizer 分层过滤同步错误、内存竞态和数值问题。

知识库

Kernel Zoo 保留具体实现与优化模式；PTX ISA 负责暴露新硬件能力，避免自然语言总结过拟合单次调试。

KCoral

远程基准服务器集中调度 GPU 请求，让 correctness、timing 与 profile 不被并发 Agent 干扰，也便于接入更多硬件。

Optimization Patterns

三个值得迁移的优化思想

这些案例的关键不是具体 trick 本身，而是 ISA、Kernel Zoo 与分析工具如何把原本偶然的专家直觉变成 Agent 可发现的路线。

用富余算力换关键路径

KDA backward 中，Agent 计算完整 64x64 矩阵再保留对角线，用 Tensor Core 算力替代共享内存 partials 与 busy warp 的 reduction，官方称约 15% latency 改善。

ISA 扩展搜索空间

MSA sparse-prefill 从 PTX ISA 找到 tcgen05.mma output-lane masking；它不减少 MMA 计算量，却提升观测频率，带来 2-3% 收益。

迁移策略而非复制代码

MSA 借 FlashAttention-4 的混合 exponential 策略缓解原生 exp 路径；KDA forward 借 GDN 层级逆分解替代串行 32x32 递推，官方称约 17% 改善。

Token Economics

先降低研发 token 成本，再谈线上单价

对推理平台而言，TIRx Harness 的第一收益是压缩工程搜索成本与 GPU 试错浪费；只有目标 kernel 是端到端瓶颈时，才可能转化为 serving goodput 与 CPM 改善。

成本公式中的位置

CPM = (Annual TCO + Engineering Cost) / Annual Goodput Tokens × 10^6

TIRx 直接作用在 Engineering Cost 与优化周期；进一步收益取决于 kernel 在端到端服务中的占比与瓶颈位置。

落地判定

场景判断
Blackwell 集群 + KDA/MSA/MLA/VSA 瓶颈高价值试点：先用 workload contract 固定正确性与基准。
多 Agent 并行调优团队KCoral 价值最高：避免共享 GPU 导致计时归因失败。
瓶颈在调度、KV cache、网络或 MoE routing优先系统 profiling；kernel harness 不是第一杠杆。
生产落地前检查清单
  • 固定 commit、依赖版本、GPU 型号、频率、workload sweep 与计时器。
  • 用上游实现做 correctness reference，并保留最小失败输入。
  • 补充 TTFT、TPOT、P99、goodput、精度衰减与长时间稳定性。
  • 确认授权：tirx-kernels 为 Apache-2.0，TIRx-harness 仓库发布时尚未标注 license。
  • 把成功 kernel、输入、trace 与命令沉淀为可复现资产，而不是只写总结。
